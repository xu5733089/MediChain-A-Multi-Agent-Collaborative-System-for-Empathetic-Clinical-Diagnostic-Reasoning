Query variants/search
Why BioLORD-2023?
Pre-trained on SNOMED CT, MeSH, and UMLS ontology pairs. Unlike all-MiniLM-L6-v2, BioLORD natively understands that "heart attack" = "myocardial infarction" = "AMI" — without keyword overlap.
Why Hybrid Search?
Dense vectors excel at semantic matching; BM25 excels at exact clinical term matching. RRF score = Σ 1/(k+rank) fuses both rankings — consistently outperforms either method alone across biomedical IR benchmarks.
New: /api/rag/ingest NEW
POST endpoint — triggers on-demand PubMed fetch and embedding without restart. Default: 60+ ICD-10 search terms covering all major clinical specialties. Custom terms accepted via request body.

Query Pipeline

6-stage pipeline from patient language to PubMed-cited diagnostic output — including multimodal image rewriting

00
Image Findings → Medical Terms NEW
Claude Vision analyses uploaded images → raw finding text → rewrite_image_findings_for_rag() → comma-separated SNOMED terms injected into RAG query
01
LLM Query Rewrite
"chest tightens when climbing stairs"
→ "stable angina, exertional chest pain, cardiac ischaemia, coronary artery disease"
Maps lay language to SNOMED CT / MeSH controlled vocabulary
02
3-Variant Query Expansion
① Raw patient text ② Medical rewrite ③ "treatment and diagnosis of {term}" ④ "What is {term}?"
Deduplicated set submitted in parallel to Qdrant
03
Qdrant Hybrid Search
For each variant: Dense (BioLORD cosine similarity) + BM25 sparse run in parallel — captures semantic similarity AND exact clinical term occurrences
04
RRF Fusion → Top 6
score = Σ 1/(k+rank) across all query variants · Threshold 0.15 · Deduplication by document ID · Documents appearing in multiple queries rank highest
05
Cited Diagnostic Output
Each diagnosis: condition name · probability · supporting passages · PubMed ID · authors · year · relevance score · clickable link

Safety & Critic Agent

Hard-coded safety rules in the Critic Agent — three escalation classes covering life-threatening presentations

🚨 Class 1 — Cardiac Emergency
Trigger: chest pain + diaphoresis + arm/jaw radiation OR crushing quality. Critic halts diagnostic chain. Output: "Call emergency services immediately (000/911)" · STEMI exclusion recommended · reasoning flagged as high-risk
🧠 Class 1 — Stroke Screening (FAST)
Trigger: sudden facial asymmetry + unilateral arm weakness + speech difficulty. Critic appends FAST protocol assessment. Output includes: "Time is brain — do not wait for an appointment. Present to emergency immediately."
⚠ Class 2 — Drug Interaction Check
If patient history lists current medications, Critic cross-checks Diagnostician's suggested treatments against known interaction profiles (e.g. NSAID + anticoagulant → GI bleeding risk · ACE inhibitor + NSAID → renal risk)
✓ Class 3 — Reasoning Transparency
Every diagnosis includes Critic verdict: "Reasoning consistent with cited evidence" OR specific objection with line-level reference. Full agent chain exportable for clinical audit.

Design Principles

Architectural decisions that ensure clinical-grade reliability, safety, and extensibility

01
Safety-First — Pre-LLM Rules
Hard-coded safety triggers evaluated before any LLM call. Pattern matching on symptom keywords is O(1) and cannot be bypassed by prompt injection or unusual phrasing.
02
Grounded Outputs — No Fabrication
Every diagnostic claim must be supported by a retrieved PubMed passage. Diagnostician is explicitly instructed: "Do not claim something not supported by the retrieved evidence."
03
Agent Separation of Concerns
Interviewer, Diagnostician, and Critic have distinct system prompts with no cross-contamination. Each agent receives only the information it needs — minimising prompt injection surface.
04
Full Audit Trail
Every agent's complete reasoning chain stored in SQLite. Provider can review, export, and dispute any AI output. Supports clinical accountability and educational use.
05
Multimodal Unification
All 6 input modalities normalise to a text context string before agent processing. DICOM→JPEG, audio→transcript, video→frame analyses — uniform interface regardless of input type.
06
Zero-Config Persistence
SQLite with FK constraints — no separate DB server required. Qdrant in embedded mode — no Qdrant server. Both run in-process alongside FastAPI for simple single-server deployment.
07
Graceful Degradation
If speech recognition unavailable (no browser support), text input remains. If RAG returns zero results above threshold, agent defaults to LLM-only with explicit "no evidence found" caveat.
08
Structured JSON Throughout
Claude instructed to output structured JSON for annotations, diagnoses, and agent verdicts. Eliminates fragile regex parsing — json.loads() with schema validation on all AI outputs.

Limitations & Future Work

Known constraints of the current implementation and planned directions for continued research

Current Limitations
No Formal Clinical Validation
Diagnostic accuracy not yet benchmarked against standardised clinical case sets (MedQA, USMLE). Safety rules are heuristic-based, not clinically audited. Not for medical use.
Single-Node Deployment
SQLite and Qdrant embedded — suitable for demo but not horizontally scalable. No load balancing, rate limiting, or multi-tenant isolation.
Corpus Currency
PubMed snapshot at ingestion time — medical knowledge not continuously updated. New research published after ingest date not retrievable.
LLM Latency
3-agent chain with RAG adds ~8–15 s per diagnostic turn depending on context length. Streaming partially mitigates perceived latency.
Future Directions
①
Formal Evaluation — MedQA Benchmark
LLM-as-judge scoring across diagnostic accuracy, empathy, hallucination rate, citation relevance. Benchmark on 50+ clinical case vignettes from MedQA dataset.
②
Reasoning Visualisation Graph
Interactive D3.js node-link diagram showing agent conversation flow, evidence retrieval nodes, and diagnostic branches with confidence scores.
③
Production Deployment
Docker Compose (frontend + FastAPI + Qdrant server + PostgreSQL) · HTTPS · OAuth2 · rate limiting · horizontal scaling via stateless agent design.
④
Continual RAG Update
Scheduled PubMed delta ingest · new publications automatically embedded and indexed · knowledge currency maintained without full re-ingest.

Key Contributions

What MediChain contributes to the state of practice in AI-assisted clinical decision support

Contribution 1
Biomedical Hybrid RAG Pipeline
Demonstrate that combining LLM query rewriting, BioLORD-2023 dense embeddings, BM25 sparse retrieval, and Reciprocal Rank Fusion over a 47,441-document PubMed corpus significantly improves medical concept recall over single-vector approaches.
Contribution 2
Multi-Agent Clinical Safety Framework
Propose a three-agent architecture where Critic serves as a pre-output safety verifier with hard-coded escalation rules evaluated pre-LLM. Separates patient interaction, diagnostic reasoning, and safety verification into independently auditable components.
Contribution 3
Multimodal Clinical Input Unification
Implement a unified preprocessing pipeline accepting 6 clinical input modalities (text, image, DICOM, audio, video, handwritten) and normalising all to structured text context before agent processing — enabling richer symptom capture than text-only systems.
Contribution 4
Empathetic AI Interviewer Design
Apply SOCRATES clinical framework within an LLM-driven conversational agent augmented with warm language conventions. Show that empathetic framing is compatible with rigorous symptom elicitation — addressing a gap in prior clinical AI dialogue systems.
